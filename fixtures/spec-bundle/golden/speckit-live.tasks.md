# Tasks: Графическая копия сайта NVIDIA (главная, продукты, меню, футер)

**Input**: Design documents from `/specs/001-nvidia-clone/`

**Prerequisites**: plan.md (required), spec.md (required for user stories), research.md, data-model.md, contracts/

**Tests**: Примеры ниже включают задачи проверки. Тесты в классическом смысле (модульные/интеграционные) в этой функции не запрашивались явно — вместо них согласно spec.md используется автоматизированное визуальное сравнение (`pixelmatch`) и ручная сверка со скриншотами оригинала как обязательный критерий приёмки каждого раздела (FR-010); соответствующие задачи включены непосредственно в реализацию каждой пользовательской истории, а не вынесены в отдельный необязательный блок.

**Organization**: Задачи сгруппированы по пользовательским историям, чтобы каждую историю можно было реализовать и проверить независимо.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Может выполняться параллельно (разные файлы, нет зависимостей между задачами).
- **[Story]**: К какой пользовательской истории относится задача (US1, US2, US3).
- В описании каждой задачи указан точный путь к файлу.

## Path Conventions

- **Единый статический проект (Single project)**: без разделения backend/frontend, так как бэкенда нет вовсе; структура зафиксирована в `plan.md`.
- Переиспользуемые фрагменты глобального меню и футера: `partials/header.html`, `partials/footer.html`.
- Исходники страниц, стилей и скриптов: `src/pages/`, `src/styles/`, `src/scripts/`.
- Локально подготовленные ассеты: `assets/images/`, `assets/icons/`, `assets/fonts/`.
- Инструменты сборки и визуальной проверки (используются только на этапе разработки, не в рантайме страниц): `tools/build.js`, `tools/visual-diff/capture.js`, `tools/visual-diff/capture-baseline.js`, `tools/visual-diff/compare.js`, `tools/visual-diff/baseline/`.
- Итоговые самодостаточные страницы — артефакт сборки, коммитятся в корень репозитория: `index.html`, `products.html`.
- «Самодостаточность» итоговых `index.html`/`products.html` означает отсутствие runtime-запросов к `partials/*.html` и к внешним доменам; CSS, JS и изображения подключаются относительными путями от корня репозитория без инлайнинга — единственное, что инлайнится при сборке, это разметка `partials/header.html` и `partials/footer.html` (FR-003, FR-009).
- Реестр расхождений: `DEVIATIONS.md` в корне репозитория.
- Пути в задачах ниже приведены с учётом этой структуры.

скрипт сопровождает эти файлы манифестом `tools/visual-diff/baseline/network/manifest.json` со списком соответствий URL → локальный файл (включая имена, изменённые из-за коллизий), который остаётся единственным надёжным источником сопоставления URL и локального файла и упрощает ручной поиск нужного ассета в T004 (используется как источник исходной разметки и файлов логотипа/иконок/шрифтов в T004)

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: без зависимостей — можно начинать сразу
- **Foundational (Phase 2)**: зависит от завершения Setup — БЛОКИРУЕТ все пользовательские истории
- **Внутри Foundational (Phase 2)**: несмотря на то, что T004 идёт по номеру раньше T005–T007, фактически T004 выполняется последней в этой фазе — после T006 (написание `capture-baseline.js`) и T007 (его однократный запуск, создающий `tools/visual-diff/baseline/source/` и `tools/visual-diff/baseline/network/`), так как T004 читает файлы, создаваемые именно в T007; это явно отражено пометкой `(depends on T006, T007)` в описании T004
- **User Stories (Phase 3+)**: все зависят от завершения Foundational-фазы
  - Пользовательские истории можно реализовывать в любом порядке после фундамента, но конституция проекта задаёт приоритет: сначала меню/футер (внутри US1), затем главная страница (US1), затем страница продуктов (US2), затем декоративные элементы (US3)
- **Polish (Final Phase)**: зависит от завершения всех желаемых пользовательских историй

### User Story Dependencies

- **User Story 1 (P1)**: можно начинать сразу после Foundational — не зависит от других историй; создаёт `partials/header.html` и `partials/footer.html`, которыми пользуется US2
- **User Story 2 (P2)**: можно начинать после Foundational, но фактически переиспользует готовые `partials/header.html`/`partials/footer.html` из US1 (T028 явно на это ссылается); тем не менее верстка `products.html` проверяется независимо от состояния `index.html`
- **User Story 3 (P3)**: можно начинать после Foundational, но осмысленно применяется только после того, как на `index.html`/`products.html` уже есть декоративные элементы, которые нужно нейтрализовать (T035 подключает скрипт в обе уже свёрстанные страницы)

### Within Each User Story

- Подготовка списка визуальных блоков — до вёрстки соответствующей разметки
- Разметка (HTML) — до стилей и скриптов, специфичных для раздела
- Сборка через `tools/build.js` — после готовности разметки и стилей
- Визуальное сравнение (`capture.js` + `compare.js`) — после сборки, до перехода к следующей истории (FR-010)
- Документирование расхождений в `DEVIATIONS.md` — последний шаг перед чек-пойнтом истории

### Parallel Opportunities

- Все задачи Setup с пометкой [P] можно выполнять параллельно
- Все задачи Foundational с пометкой [P] можно выполнять параллельно (в рамках Phase 2)
- Внутри пользовательской истории задачи фиксации списков визуальных блоков (например, T012 и T013, или T017 и T024) можно выполнять параллельно, так как они не зависят друг от друга
- Поскольку проект ведётся одним человеком (solution/audience_size: only_me), «параллельность» здесь означает порядок, в котором удобно переключаться между независимыми задачами в рамках одной сессии, а не распределение между разными исполнителями

## Implementation Strategy

### MVP First (User Story 1 Only)

1. Завершить Phase 1: Setup
2. Завершить Phase 2: Foundational (КРИТИЧНО — блокирует все истории)
3. Завершить Phase 3: User Story 1 (главная страница + глобальное меню + футер)
4. **Остановиться и проверить**: убедиться, что `index.html` проходит визуальное сравнение независимо от остальных страниц
5. На этом этапе уже достигнута ключевая цель проекта — пиксельно точная главная страница, доступная офлайн

### Incremental Delivery

1. Setup + Foundational → готов фундамент (partials-инфраструктура, build-скрипт, инструменты визуального сравнения)
2. Добавить User Story 1 → проверить независимо → главная страница готова к демонстрации (MVP)
3. Добавить User Story 2 → проверить независимо → добавлена страница продуктов, меню/футер переиспользованы без изменений
4. Добавить User Story 3 → проверить независимо → декоративные элементы больше не выглядят «сломанными» при клике
5. Каждая история добавляет ценность, не нарушая уже проверенные предыдущие истории

### Notes on Solo Execution

Проект ведётся одним человеком без выделенной команды (solution/audience_size: only_me, tasks/builder_comfort: just_result), поэтому фазы выполняются последовательно в порядке приоритета P1 → P2 → P3, а пометка [P] используется как ориентир, какие задачи можно переключать местами внутри одной рабочей сессии, а не как распределение работы между разными людьми.

## Notes

- [P] задачи = разные файлы, нет зависимостей между собой
- Пометка [Story] связывает задачу с конкретной пользовательской историей для отслеживания
- Каждая пользовательская история должна оставаться независимо завершаемой и проверяемой
- Перед переходом к следующему разделу обязательно пройти визуальное сравнение (`compare.js`) и зафиксировать неустранённые расхождения в `DEVIATIONS.md` (FR-010, FR-011) — это заменяет здесь классический шаг «убедиться, что тесты падают до реализации»
- Дедлайна у проекта нет (tasks/deadline: no_deadline), поэтому порядок фаз важнее скорости: не пропускать шаг визуальной сверки ради ускорения
- Не расширять охват за пределы главной страницы, страницы продуктов, глобального меню и футера — любые дополнительные страницы (корзина, поиск, авторизация и т.д.) требуют нового явного запроса владельца проекта, а не могут появиться как побочный эффект задач из этого списка
- Избегать: расплывчатых задач, конфликтов при работе с одним и тем же файлом, кросс-историчных зависимостей, нарушающих независимость пользовательских историй
