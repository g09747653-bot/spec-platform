## Обзор

Тот же план, что и живой слепок M14а — консольный планировщик личных дел на Python 3.10+ с
локальной SQLite, автоматическими резервными копиями и ротацией, — записанный так, как теперь
велит инструкция генерации плана: сквозные номера задач и явная строка зависимостей у каждой
задачи, включая задачи, не зависящие ни от чего. Зависимости названы по прямым предпосылкам кода
из текста задач живого слепка: задача заявляет ровно те задачи, чей продукт использует её код.

## Задачи

- [ ] 1. Определение и разрешение путей рабочей директории
  - Логика определения пути рабочей директории на основе переменной окружения `TODO_WORK_DIR` или системных путей по умолчанию (`~/.config/todo/` для Linux/macOS и `%APPDATA%/todo/` для Windows). Путь корректно преобразуется в абсолютный; `~` разворачивается в UNIX-системах.
  - _Зависимости: —_
- [ ] 2. Создание структуры папок и разграничение прав доступа
  - Автоматическое создание рабочей директории и поддиректории `backups` по вычисленным путям. На UNIX-подобных системах — права `0700` для создаваемых директорий.
  - _Зависимости: 1_
- [ ] 3. Инициализация базы данных и схемы (clean_slate)
  - Проверка наличия файла `todo.db` в вычисленной рабочей директории; отсутствующий файл создаётся автоматически с правами `0600` на POSIX. Разворачивается схема таблицы `tasks` и индексы `idx_tasks_due_date`, `idx_tasks_is_completed`. Инициализация с чистого листа, без исторических миграций.
  - _Зависимости: 1_
- [ ] 4. Реализация репозитория задач (TaskRepository)
  - Класс репозитория для работы с SQLite поверх развёрнутой схемы: `insert_task`, `get_task_by_id`, `update_task_status`, `fetch_active_tasks`, `fetch_all_tasks`. Только параметризованные запросы; записи — строго в транзакциях.
  - _Зависимости: 3_
- [ ] 5. Механизм автоматического бэкапа перед транзакциями записи
  - Модуль `BackupService`, копирующий рабочий файл `todo.db` в папку `backups` перед любой транзакцией записи. Имя копии — `todo.db.bak.YYYYMMDDHHMMSSffffff` по UTC. При ошибке бэкапа транзакция прерывается, сообщение в `stderr`, код `1`.
  - _Зависимости: 3_
- [ ] 6. Алгоритм ротации резервных копий
  - После успешного создания новой копии — контроль количества бэкап-файлов: старше пяти сортируются лексикографически, самый старый удаляется. В папке всегда ровно пять последних копий.
  - _Зависимости: 5_
- [ ] 7. Валидация входных данных бизнес-слоя
  - Валидация заголовка задачи (не пустой, не только пробелы) и даты (формат `YYYY-MM-DD`, реальная календарная дата в диапазоне 1900–2100). Ошибки — исключения бизнес-логики.
  - _Зависимости: —_
- [ ] 8. Логика фильтрации задач на сегодня (overdue_included / auto_include)
  - Текущая локальная дата вычисляется приложением (не SQLite). Без `--all` — невыполненные с `due_date <= local_today`; с `--all` — плюс выполненные за сегодня. Сортировка по `due_date`, затем по `id`. Выборка — методами репозитория.
  - _Зависимости: 4_
- [ ] 9. Идемпотентность закрытия задач (noop для todo done)
  - Перед отметкой выполнения — проверка текущего статуса через репозиторий: уже выполненная задача не открывает транзакцию и не создаёт бэкап, возврат успешный (код `0`).
  - _Зависимости: 4, 5_
- [ ] 10. Разбор аргументов командной строки (CLI Parser)
  - `argparse` с тремя командами: `add`, `list`, `done`. Опущенный `--date` у `add` — текущая локальная дата. Синтаксические ошибки — справка в `stderr` и код `2`; нечисловой или неположительный id в `done` — код `2`.
  - _Зависимости: —_
- [ ] 11. Форматирование вывода в stdout
  - Вывод результатов команд: `add` печатает только ID; `done` молчит; `list` — строки `<id>\t<статус>\t<дата>\t<название>` без заголовков, статусы `[ ]` и `[X]`. Без декоративных элементов.
  - _Зависимости: 10_
- [ ] 12. Централизованная обработка ошибок и кодов возврата (Exit Codes)
  - Перехват системных и семантических исключений в точке входа: ошибки прав, формата даты, несуществующего ID. Лаконичное сообщение на русском в `stderr` без stack trace, код `1`.
  - _Зависимости: 7, 10_
- [ ] 13. Реализация опционального отладочного логирования (TODO_DEBUG=1)
  - При `TODO_DEBUG=1` — запись SQL-запросов и stack trace в `todo.log` в вычисленной рабочей директории через ротируемый обработчик с лимитом размера. По умолчанию файл не создаётся.
  - _Зависимости: 1_
- [ ] 14. Модульные тесты (Unit Tests)
  - Тесты парсера аргументов (включая дату по умолчанию у `add`), валидатора дат и правил фильтрации задач.
  - _Зависимости: 7, 8, 10_
- [ ] 15. Интеграционные тесты (Integration Tests)
  - Тесты инициализации БД (clean_slate), транзакционности записи, создания и ротации бэкапов, прав доступа к создаваемым файлам.
  - _Зависимости: 3, 4, 5, 6_
- [ ] 16. Системные E2E-тесты (CLI Tests)
  - Автоматизированный запуск утилиты в изолированном окружении: коды возврата процесса (включая noop у `done`), сопоставление `stdout`/`stderr` с эталонами.
  - _Зависимости: 9, 11, 12_
