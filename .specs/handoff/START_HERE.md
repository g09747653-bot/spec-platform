## Дефект D-BUILD-1 (приоритет: чинить первым)

Прод-сборка на Vercel: `pnpm db:migrate` отработал (**`Migrations applied.`** — это доказательство для AC задачи 9), затем `next build` упал в `next.config.ts` → `getEnv()`:

```
Error [EnvironmentConfigurationError]: Invalid environment configuration...
  - AUTH_SECRET: Too small: expected string to have >=1 characters
  - AUTH_URL: Invalid URL
  ... (все 12 milestone-переменных)
```

Разбор Архитектора: схема объявляет их `z.string().min(1).optional()`. `.optional()` пропускает `undefined`, но **не пустую строку** — а платформа сборки отдаёт объявленную-но-незаполненную переменную именно пустой строкой. Локально дефект не виден, потому что в `.env` этих ключей нет вовсе. Класс ошибки: «пустая строка ≠ отсутствие значения».

Требование к исправлению (уровень 1, AC задачи 7 не меняются):

1. Для **optional**-переменных пустая строка и строка из пробелов трактуются как отсутствие значения (нормализация на входе `parseEnv`, а не заплатка на каждом поле).
2. Для **обязательных** переменных поведение прежнее: пустая строка = ошибка с именем переменной (AC задачи 7 обязан продолжать выполняться — проверь).
3. Unit-тесты на оба случая: `{DATABASE_URL:'x', AUTH_SECRET:''}` парсится успешно; `{DATABASE_URL:''}` падает с именем `DATABASE_URL`.
4. **Источник установлен** (диагностика не нужна): при импорте Vercel читает `.env.example` из репозитория и предлагает завести все объявленные там ключи — заказчик подтвердил плашку «24 Env Variables To Review». Незаполненные ключи попали в окружение сборки пустыми строками. Заказчик чистит проект до двух записей `DATABASE_URL` (Production + Preview), но загрузчик обязан быть устойчивым к этому классу входа независимо от чистки — это и есть суть фикса.
5. Запиши `D-12` в decisions.md.

После фикса — push; он же запустит CI и новый прод-деплой. Прод-деплой обязан стать зелёным, иначе задача 9 не закрывается.
