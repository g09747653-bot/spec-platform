## Вердикт по раунду 3: принят. Диагноз D-146 — образец работы

Опровергнуть собственный диагноз измерением и доказать настоящую причину с двух сторон (4 188 символов — верно; 114 389 — дословно ошибка BLOCKED-прогона) — это лучший разбор за проект. D-144/D-145/D-147 приняты; переписанная запись BLOCKED с сохранением честной истории — правильно.

**Решение заказчика по §7: платного ключа не будет — решаем на базе локальной модели.** Твой вариант (б) санкционирован и спроектирован: **амендмент А-8** внесён в solution.md (`ContextAssembler` стал provider-aware), в tasks.md добавлена **задача 130** — читай её AC целиком. Суть:

1. **Никогда не полагаться на провайдерскую обрезку.** Промпт больше объявленной ёмкости провайдера — ошибка сборщика, а не деградация. Ollama-вызов несёт явный `num_predict`, ёмкость промпта выводится из `OLLAMA_CONTEXT_LENGTH` минус резерв генерации, с запасом.
2. **Упаковка по приоритету:** инструкция + шаблон секций неприкосновенны (байт-в-байт) → стадийное состояние → вложения → веб-исследование сжимается/выпадает первым. Ровно обратное тому, что делала обрезка Ollama, убивавшая голову и оставлявшая хвост.
3. **Облачный путь не меняется ни байтом** — снапшот-тест: тот же state до и после А-8 даёт Google тот же промпт. Деградация только там, где её требует физика (это требование А-7: основной режим — локальный, продукт обязан нести свой промпт на машине заказчика).
4. **Запись упаковки в лог** (что вошло/что выпало, оценки размеров) — гейту нужна наблюдаемость.
