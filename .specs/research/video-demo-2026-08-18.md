## 1. Предпросмотр плана — это **оверлей**, а не колонка

- Центрированное модальное окно поверх ленты; лента видна по краям и приглушена.
- Шапка слева: иконка файла, `tasks.md`, под ним второй строкой `Revision 2`.
- Шапка справа, одной линией: `⌸ Outline` · сегментированный переключатель `Preview | Raw | Diff`
  (активный залит синим) · `⧉ Copy` · `⤓ Download` · `✕`.
- **Ширина оверлея одинакова во всех трёх вкладках** и меньше окна; собственная полоса прокрутки —
  внутри оверлея. Ни в одном кадре содержимое не выталкивает окно за экран.
- `Outline` — **выпадающая панель, приколотая к своей кнопке** (кадр 11), а не постоянная колонка:
  список заголовков поверх документа, документ виден под ним.

## 2. `Raw` эталона **переносит длинные строки**

1165, 1175, 1186 в кадре 46). Горизонтальной прокрутки нет ни в одном кадре `Raw`.

> **Расхождение с нашим AC.** Задача 142 предписывает нам «длинные строки — горизонтальная прокрутка
> ВНУТРИ колодца кода». Эталон решает ту же проблему переносом. Реализуем по AC (это контракт),
> расхождение вносится в таблицу сверки гейта 146 как осознанное, а не как незамеченное.

- Шапка: `Needs Revision` / `Pass` (бейдж) + подпись `Tasks review`.
- Абзац-резюме на всю ширину.
- Группы-раскрывашки: `Must Fix` **3**, `Recommendations` **7** — счётчик в самом заголовке.
- Пункт: чекбокс, заголовок вида `Milestone 1 — Task 22 (Walking Skeleton)`, **бейдж оценки справа

## 5. Типы ответов: опция несёт **справку**

Главное открытие видео (кадры 57–75, кроп в полном разрешении).

Опция, называющая реальную технологию, состоит из:

1. радиокнопки/чекбокса;
2. **логотипа** технологии (Anthropic, OpenAI, OpenRouter, Next.js, React, Neon, MongoDB, SQLite);
3. текста опции;
4. `(Recommended)` отдельным цветом — на нескольких опциях одного вопроса одновременно;
5. **иконки внешней ссылки ↗** — на сайт технологии;
6. **иконки ⓘ** — справка;
7. **строки тег-чипов** под текстом: `ai · llm · provider · api · foundation-model · reasoning ·
   commercial`; `framework · react · ssr · frontend · meta-framework · javascript · web`;
   `authentication · cloud-computing-platform · database · storage`; `sql · database · db`.

Опции, не называющие технологию (`No preference — recommend the best fit`, `Bring-your-own-key`,
`Other`, и все опции нетехнических вопросов — кадр 51), идут **без логотипа, ссылки, ⓘ и тегов**.
То есть справка — свойство опции, а не оформление вопроса.

`Other` при выборе раскрывает поле свободного текста прямо под собой.

Разметка вопроса: жирный текст, красная `*` для обязательного, под ним разрядкой капслоком
`SELECT ONE` / `SELECT ALL THAT APPLY`. Заголовок раунда — `ROUND 1 — 5 QUESTIONS`.

> У нас тег-чипы опций уже есть (D-188, до четырёх ярлыков). Логотипа, ссылки и ⓘ — нет.
> Это материал задачи 144 (справки при ответах), не 142.

## 6. Голос эталонного интервьюера

Между раундами — короткая реплика от первого лица, подводящая итог и объявляющая следующий шаг:

- «Locked in: multi-provider LLM abstraction with fallback, Next.js + TypeScript, PostgreSQL with an
  ORM, modular monolith with an explicit agent state machine, and determinism plus human approval
  gates as the governing principles.»
- «One last round to cover testing, standards, security, performance, and integrations — then I'll
  draft the constitution.»
- «All inputs gathered. Since execution mode should adapt to whoever picks the plan up, I'll make
  every task self-describing … so a solo developer with an agent and a small team can both work from
  the same list.»

Вопросы эталона предметны сами по себе: «In what order should the work be sequenced?», «Who will
execute this plan?», «What metadata should each task carry?», «How should the plan be grouped?»,
«What should the persistence layer be?». Материал для рубрики задачи 144.

## 7. Чего в видео НЕТ

Ни одного кадра с неодобренным документом, с панелью стадии, с ожиданием ворот или с кнопкой
`Approve`: чат в видео уже `Completed`, и все карточки документов — `Approved`. Поэтому **эталонной
подачи панели стадии видео не даёт**; иерархию панели (третий дефект задачи 142) строим от
требования «одно главное действие на состояние», а не от кадра.
