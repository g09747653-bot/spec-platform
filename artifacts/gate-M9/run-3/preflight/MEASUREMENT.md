# Предполётный замер модели — раунд 3 (D-144, D-146)

Замер по образцу D-91: одна генерация на **собственном промпте репозитория** для SpecKit-конституции
(`spec.generation.methodology.v1`), шаблон и список обязательных секций взяты из вендоренного файла
через `templateText` / `templateSections`, вердикт вынесен продуктовой `validateAgainstSections`.
Ничего не переписано рядом — измерялся тот промпт, который отправляет продукт.

Обязательных секций у этого шаблона две: `## Core Principles`, `## Governance`. Это ровно те две,
которыми гейт падал в прогонах 1–2.

## 1. Модели на коротком промпте (4 188 символов)

| модель | структура | первый токен | весь документ | размещение | документ |
|---|---|---|---|---|---|
| `qwen3.8:27b` (выбор заказчика) | **верна** | 229,8 с | **473,9 с** | 33 % / 67 % CPU/GPU | `speckit-constitution-qwen3.8-27b.md` |
| `qwen3:14b` (fallback, взят) | **верна** | 20,2 с | **32,4 с** | 100 % GPU | `speckit-constitution-qwen3-14b.md` |
| `qwen2.5:14b-instruct-q4_K_M` (прежняя) | **верна** | 7,4 с | 15,5 с | 100 % GPU | `speckit-constitution-qwen2.5-14b.md` |

Бюджет — 300 с (`LLM_REQUEST_TIMEOUT_MS`, `scripts/dev-gate.mjs`). 27B мимо на 174 с: 16,8 ГБ весов
не помещаются в 16 GiB VRAM. Отсюда fallback по START_HERE §2 → `qwen3:14b` (D-144).

**Третья строка — главная.** Прежняя модель пишет конформный документ за 15,5 с. Значит версия
«локальная модель этого размера не воспроизводит обязательные заголовки», на которой стоял BLOCKED
раундов 1–2, неверна.

## 2. Тот же промпт, доведённый до потолка сборщика контекста

`DEFAULT_CONTEXT_BUDGET` = 120 000 символов. Исследование выполняется на **каждой** генерации
документа, `WEB_FETCH_MAX_BYTES` = 1 МБ × `PAGES_TO_READ` = 2 — то есть до потолка контекст добирает
всегда, а не изредка.

| промпт | модель | результат |
|---|---|---|
| 4 188 символов | `qwen2.5:14b` | структура **верна** |
| 114 389 символов | `qwen2.5:14b` | `missing section "## Core Principles"; missing section "## Governance"` |

Вторая строка — слово в слово запись из BLOCKED прогона 2. Документ: `overflow-qwen2.5-14b.md`; его
заголовки — `#### RQ Platform`, `#### Reviewr`, `### Conclusion: Choose by Team Size`, то есть
пересказ веб-исследования, а не конституция.

## 3. Почему: Ollama сообщает об этом сама

```
level=WARN source=llama_server.go:315 msg="truncating input prompt" limit=8194 prompt=22223 keep=4 new=8194
```

При `OLLAMA_CONTEXT_LENGTH=16384` под промпт отдаётся **половина** окна (`limit=8194`). Промпт на
22 223 токена режется до 8 194, `keep=4` — от начала остаются четыре токена. Системная инструкция и
список обязательных секций выбрасываются целиком; выживает хвост, то есть веб-исследование. Модель
пишет ровно его. Обрезка детерминирована — поэтому три повтора D-142 давали один и тот же дефект.

## 4. Второе положение окна не спасает

`OLLAMA_CONTEXT_LENGTH=32768`, `qwen3:14b`, тот же промпт на 114 389 символов:

- обрезки **ноль** (записей `truncating input prompt` в логе нет) — промпт помещается целиком;
- модель уходит на 10 % в CPU (`ollama ps` → `10%/90% CPU/GPU`);
- чтение промпта идёт **~40 токенов/с**: за 302 с прочитано 10 240 токенов из 22 223, до генерации
  дело не дошло. Полный промпт потребовал бы ≈9 минут только на чтение.

16384 — быстро и слепо; 32768 — зряче и не успевает. Размер модели не влияет ни на первое, ни на
второе. Лог: `../ollama-32k.err`.
