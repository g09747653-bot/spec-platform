## Project Vision

Цель проекта — создание сверхбыстрой утилиты командной строки (CLI) для мгновенной конвертации величин (длина, масса, температура), которая решает проблему частого переключения контекста (`context_switch`) у разработчиков.

Вместо открытия браузера и использования веб-поиска (`google_search`), разработчик получает локальный инструмент прямо в терминале. Утилита предоставляет мгновенный доступ к истории последних операций, хранящейся локально, что позволяет быстро возвращаться к недавним вычислениям. Успех продукта определяется его способностью стать ежедневной привычкой пользователя (`daily_habit`), обеспечивая выполнение операций в разы быстрее, чем любой онлайн-аналог (`faster_than_search`).

## Core Principles

При разработке утилиты необходимо руководствоваться следующими незыблемыми принципами:

*   **Абсолютная локальность и приватность**: Полное отсутствие сетевых запросов (`no_network`) и передачи каких-либо данных на внешние сервера (`no_data_send`). Вся работа происходит исключительно на машине пользователя.
*   **Бескомпромиссная точность**: Исключение любых ошибок округления (`no_wrong_rounding`). Конвертация должна выполняться строго в соответствии с физическими и математическими стандартами.
*   **Отсутствие неявных перезаписей**: История и пользовательские файлы не должны перезаписываться непредсказуемым образом (`no_silent_overwrite`). Ротация и обновление логов истории должны следовать строго детерминированному алгоритму.
*   **Простота и фокус**: Утилита должна делать только одну вещь и делать её превосходно. Мы полностью отказываемся от:
    *   Графического интерфейса (`no_gui`).
    *   Поддержки курсов валют (`no_currency`), так как они требуют обновления по сети.
    *   Синхронизации с облаком (`no_cloud_sync`).
    *   Кастомных (пользовательских) единиц измерения (`no_custom_units`).
*   **Удобство для разработчиков**: Лаконичный синтаксис команд, поддержка пайпов (pipes), автодополнение и понятный формат вывода.

## Technology Constraints

*   **Среда выполнения**: Утилита должна быть кроссплатформенной и работать на macOS, Linux и Windows. Рекомендуется использовать Node.js (пакет, распространяемый через npm/npx) или скомпилированный бинарный файл (например, на Go или Rust) для обеспечения максимальной скорости запуска.
*   **Зависимости**: Минимальное количество внешних библиотек. Полный запрет на любые зависимости, требующие сетевого подключения в процессе работы программы.
*   **Хранение данных**: Локальный файл истории должен храниться в формате JSON в стандартной директории конфигурации пользователя (например, `~/.config/` или `~/.local/share/` в соответствии со спецификацией XDG).

## Architecture Constraints

*   **Интерфейс командной строки (CLI)**:
    *   Поддержка прямого вызова с аргументами: `convert <значение> <из_чего> <в_что>` (например, `convert 100 kg lb`).
    *   Интерактивный режим при запуске без аргументов.
    *   Флаги для просмотра истории (`--history` / `-h`) и очистки истории (`--clear`).
*   **Категории величин**:
    *   **Длина**: метрические (миллиметры, сантиметры, метры, километры) и имперские (дюймы, футы, ярды, мили).
    *   **Масса**: граммы, килограммы, тонны, унции, фунты.
    *   **Температура**: Цельсий (°C), Фаренгейт (°F), Кельвин (K) с использованием строгих формул преобразования.
*   **Управление историей**:
    *   Ограничение размера файла истории (хранение последних N записей, по умолчанию 50).
    *   Атомарная запись в файл истории: запись во временный файл с последующим переименованием для исключения повреждения данных при внезапном прерывании процесса.
    *   Если файл истории поврежден, утилита должна автоматически восстанавливать его структуру (пустой список) без аварийного завершения работы.

## Testing Approaches

*   **Модульное тестирование (Unit Tests)**:
    *   100% покрытие математических формул конвертации. Особое внимание уделить критическим точкам (абсолютный ноль для температур, нулевые и отрицательные значения массы/длины).
    *   Тестирование парсера аргументов командной строки на валидные и невалидные входные данные.
*   **Интеграционное тестирование**:
    *   Эмуляция работы с файловой системой через моки для проверки чтения, записи, ротации и восстановления поврежденного файла истории.
    *   Проверка корректности работы CLI в различных кодировках и на различных операционных системах.
*   **Тестирование производительности**:
    *   Автоматизированный замер времени холодного старта утилиты.

## Coding Standards

*   **Чистота кода**: Использование строгой типизации (TypeScript при использовании Node.js).
*   **Предсказуемость ошибок**: Каждая ошибка должна иметь понятный код (Exit Code) и выводиться в поток `stderr` с четким описанием проблемы и подсказкой по её устранению.
*   **Форматирование**: Код должен быть отформатирован в соответствии со стандартами сообщества (например, Prettier/ESLint для JS/TS).
*   **Отсутствие магии**: Константы для коэффициентов конвертации должны быть жестко зафиксированы в коде, снабжены комментариями со ссылками на стандарты мер и весов.

## Security Constraints

*   **Сетевая безопасность**: Полное отсутствие кода, инициализирующего сокеты, HTTP-запросы или DNS-разрешения.
*   **Доступ к файловой системе**: Утилита имеет право читать и писать только в свой собственный конфигурационный файл истории. Запрещен доступ к любым другим директориям за пределами домашней папки пользователя.
*   **Валидация ввода**: Строгая санитария всех входных параметров командной строки для предотвращения атак типа Argument Injection.

## Performance Targets

*   **Время запуска**: Менее 50 миллисекунд от момента вызова команды до вывода результата в терминал (это ключевой фактор для победы над `google_search`).
*   **Использование памяти**: Минимальный объем оперативной памяти при работе (не более 30 МБ).
*   **Размер дистрибутива**: Легковесный исполняемый файл или пакет, не требующий тяжелых зависимостей для установки.

## Integration Points

*   **Стандартные потоки**:
    *   `stdout` — для вывода результатов конвертации и истории. Формат должен быть удобен для парсинга другими утилитами (например, через grep, awk) при использовании флагов тишины (`--quiet` / `-q`).
    *   `stderr` — для вывода ошибок валидации и системных сбоев.
*   **Окружение (Shell)**: Утилита должна корректно поддерживать работу в bash, zsh, fish и Windows PowerShell, включая генерацию скриптов автодополнения (tab completion) для единиц измерения.
